## Файловая структура
- App routing: в папках маршрутов лежит то, что нужно там. Названия папок компонентов начинаются с `_`.
- В `src/shared/**/*` вынесен код, который используется в нескольких частях приложения.

## Парадигма
- Работа с ядром API части `src/shared/api` написана на ООП.
- Остальная часть написана на ФП.

## Работа с HTTP
- Server action вместо API routing. Actions лежат там, где используются.
- Доступ к HTTP-серверу через фасад HttpClient (экземпляр синглтона называется `http`).
- Fetch бывает клиентский и серверный:
  - Получить клиентский HTTP-клиент можно через `http.client`, например `http.client.getSomethingClient()`.
  - Создать серверный HTTP-клиент можно через `http.server`, например `http.server.createSomethingClient()`.
  - После получения/создания клиента можно пользоваться его методами.

## Работа с WebSocket
- Доступ к WS-серверу через фасад WebSocketClient (экземпляр синглтона называется `ws`).
- Подписка на событие через `ws.on("событие", коллбек)` (паттерн Observer).
- Сообщить о событии через `ws.notify.событие()`.
- При подписке события не стоит забывать отписываться при размонтировании компонента.

## Обработка ошибок
- Для работы с ошибками используются функции/классы из `shared/utils/Error/`.
- Actions могут возвращать ошибку `AppError`.
- Все ошибки, пойманные или обработанные при получении через `isAppError`, передаются в функцию `showError()` из `shared/utils/Error/`.
- Главное правило:
  - неправильное действие возвращает ошибку `AppError`;
  - все пойманные в Server Action ошибки возвращаются, а пойманные в серверных компонентах просто выбрасываются;
  - все пойманные/полученные на клиенте ошибки вручную передаются в `showError()`.
